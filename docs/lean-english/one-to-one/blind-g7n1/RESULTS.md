## Corrections to the English

1. **Claim 1, “Does NOT say”: the unconditional rollback-then-write halt assertion is false.** Replace that aside with: “The theorem guarantees safety, not progress. Restoring a stale record and then attempting a write sets the halt flag; restoring the current anchored record need not halt and can permit further commits. Recovery behavior is governed by the modeled restart and record-restoration steps.” The separately gated witness contains both a stale rollback that halts and a rollback to the current committed record followed by a successful second commit. The trace of the latter is `write 5; bump; rollback 1; write 6; bump`.

2. **Claim 2, collision-resistance premise:** replace “not provable in Lean for a compressing hash” with: “For the arbitrary run considered here, assume the head function is injective on the accepted manifests and independently anchored logs in that run. This finite-set property may be provable for a particular specified run, even with a compressing hash. Global injectivity of a fixed-width hash on all lists is impossible.” Compression does not prevent proving collision freedom on a specified finite set. The gate witnesses establish actual nonempty acceptance and the required per-run injectivity in toy instances; no theorem about SHA-256 is claimed.

3. **Claim 5, main sentence:** replace with: “From the empty state, run any finite sequence of operations with the extension-only witness enabled. If the chain head is injective on the accepted manifests and anchored logs of the final state, every accepted manifest equals an anchored log and is a prefix of the witness's latest anchored log.” This states the omitted initialization and retains acceptance of earlier anchors.

4. **Claim 6, invariant description:** replace the parenthetical with: “The starting state satisfies the full model invariant: anchor heads match their lists, anchors form a prefix chain and are prefixes of the recorded last anchor, every recorded last anchor has an anchor entry, and every accepted manifest has a matching anchor head.” The omitted field is `Inv.lastAnch`. The actual Back already uses the full `Inv`, so this is a prose correction rather than a Back mismatch.

5. **Claim 9, main sentence:** replace with: “Starting from the empty concrete state `cinit`, run any finite trace in the concrete machine with writer-published heads untrusted. Assuming `TraceInj` across that trace and head injectivity on the final accepted and independently anchored lists, every accepted manifest equals a witness-anchored list and is a prefix of the latest ghost anchor.” Clarify the premises with: “The transition system gives the writer no operation that overwrites witness memory or log. Whether deployed memory, logs and fsync provide this persistence and independence is an external correspondence assumption.” Actual fsync behavior is not a predicate checked by this declaration.

6. **Claim 10, main sentence:** replace with: “Starting from `cinit`, split any finite concrete trace into `pre` and `post`. Under `TraceInj` for `pre ++ post`, if `l` is an anchored ghost list after `pre`, every anchor value after the combined trace is either already in the anchor log after `pre`, or has a ghost list extending `l`.” Keep the qualification that no final accepted-set injectivity is needed.

Claims 3, 4, 7 and 8 need no replacement for the theorem statement.

## Ambiguities exposed

- **Initialization (5, 9, 10):** the prose does not explicitly quantify the starting state. Phase A documented a choice of `init`/`cinit`, which exactly matches the originals. Allowing arbitrary starting states without invariant hypotheses would change the claims: a fabricated starting accepted list with no anchor already violates the proposed safety conclusion. An arbitrary witness log and inconsistent witness memory also invalidate the concrete transfer argument. The EQUIVALENT verdicts are conditional on the saved Back reading, not evidence that the omission is harmless.
- **Rollback versus stale rollback (1):** `rollback k` can select the current committed record, an older record, or an out-of-range index that does nothing. “Rollback” alone does not imply staleness. A halt is also not an immutable state property in this anti-rollback machine: restart has modeled recovery branches. Claim 4's absorbing halt belongs to a different machine.
- **World premises versus construction (1, 2, 5, 7, 9, 10):** anchor trust, record integrity, witness independence and deployment correspondence are encoded through the permitted transitions or assumed externally. The iff checks do not establish trusted hardware, real hash collision resistance, real fsync durability, or Python implementation correctness.
- **Invariant shorthand (6):** “the invariant” can refer to the named full structure, or readers can mistake the parenthetical for an exhaustive list. The latter omits `lastAnch`. Also, “matching anchor” means matching head in `Inv.acc`; list equality for accepted manifests additionally needs injectivity.
- **Old records versus new occurrences (6, 10):** `a ∈ oldAnchors` is list membership of a `(head, ghost-list)` value. The conclusion has no timestamps or occurrence identities. Preserve the literal old-value-or-extension wording; do not turn the theorem into an event-indexed statement without a separate argument.
- **“Does NOT say” audit:** 1 respects safety-only, commit-only effects and unproved hardware trust, except for the overbroad halt aside corrected above. 2 respects non-genuine contents, older anchors and rewrite laundering; its witness computes both laundering before anchoring and older-anchor acceptance. 3 remains exactly two examples with a toy hash; its witness additionally checks honest acceptance, without generalizing detection. 4 respects model-only state freeze and no liveness/credential guarantee. 5 respects earlier-anchor acceptance and untrusted contents; its witness accepts `[5]` when the latest anchor is `[5,6]`. 6 respects arbitrary appended contents, unauthenticated first anchor and lack of an acceptance conclusion. 7 respects lack of content truth or verifier conclusions. 8 respects absence of alarm-consumption and real-runtime guarantees. 9 respects the implementation gap, older-anchor acceptance and concrete empty-truncation silence; its witness computes that truncation adds neither a fork record nor an anchor. 10 respects arbitrary extending contents, first-anchor limitation and the empty-truncation limitation. These limitations are not promoted into extra safety guarantees.
