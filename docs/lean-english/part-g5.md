# Plain-English statements, part G5 (SC-21, SC-22, SC-23, SC-24)

All file paths are relative to `/var/tmp/sol-deployment-slice-20261010`. Line numbers are those of the `theorem` keyword.
Shared vocabulary used below:

- "Trace" / "any trace": any finite list of operations, chosen by the adversary, fed to the model's step function.
- "Hidden random sample": a size-B subset S of N rounds/tasks/findings, drawn uniformly at random, with the model giving the adversary no information about it except through "caught" flags.
- `C(a,b)` is the binomial coefficient "a choose b".

## SC-21 — Agent corrupts safety evaluations or selectively suppresses failures

**Harm:** A published evaluation omits frozen tasks, uses a modified evaluator, or misstates a re-executed task's result; and if k results are corrupted, they escape a hidden re-execution sample of size B with probability above C(N−k,B)/C(N,B).

**What the Lean claims, taken together, and what they leave to assumptions.** There are two separate Lean models that are never connected to each other. (1) A deterministic publication-gate model (`sc21_safe`): whatever gets published covers every frozen task, carries the frozen evaluator digest on every result, and every result for a task that was re-executed is the true value; but which tasks get re-executed is chosen by the trace, so nothing is said about how many corruptions get caught. (2) A probability model (`sc21_undetected_prob`, `sc21_undetected_le_pow`, `sc21_adaptive*`): for a hidden uniformly random sample of B of N results, the chance that k corrupted results are all missed is at most C(N−k,B)/C(N,B), also against an adaptive corrupter who sees only its own earlier choices and catch flags. This is an upper bound on escape, not a guarantee of detection (for N=100, B=10, k=5 the escape probability is about 0.58). Everything rests on the assumptions that the sample is truly hidden, that re-execution is deterministic (or has recall at least r), that the digest field truthfully identifies the evaluator, and that trusted identities (admin halt, executor, publisher) are not forgeable (credential separation, not modelled).

### `ControlStack.EvalIntegrity.sc21_safe`  — `ControlStack/Scenarios/EvalIntegrity.lean:218`
- **Says (plain English):** Start from an empty state and apply any list of operations (report a result for a task with a claimed value and an evaluator digest, re-execute a task, attempt to publish, halt) under the full set of checks. Then every record that was published (a snapshot of the results log plus the list of tasks re-executed so far) satisfies three things: every task on the frozen task list has a result in the snapshot; every result in the snapshot carries the frozen evaluator's digest; and every result in the snapshot whose task had been re-executed by then holds the true value for that task.
- **Under these hypotheses:** The environment (task list, a truth function, a frozen digest, a list of admin ids) is arbitrary but fixed. The "full" checks are all on: the results log is append-only (a second report for the same task is ignored), publication requires that every task has a result, that every stored result has the frozen digest, and that no flag has ever been raised, and re-executing a task compares the stored value to the environment's truth function and raises a permanent flag on mismatch. World assumptions, not provable in Lean: the digest attached to a report is honest (in the model it is just a number supplied with the `report` operation; nothing ties it to the evaluator actually run); re-execution returns the model's truth value (deterministic re-execution); the re-execution and publish operations are performed by an executor and publisher independent of the agent.
- **Does NOT say:** (a) That corrupted results are caught: the trace decides which tasks (if any) are re-executed, so a trace that re-executes nothing publishes unchecked values. How likely a hidden sample is to catch corruption is a different model (the sampling theorems). (b) That tasks and evaluator measure the intended capability, or that the digest equals the evaluator that actually ran. (c) Anything about values of results for tasks that were not re-executed.
- **Kind:** general theorem (induction over traces; the safety statement is an invariant of the model).
- **Non-vacuity:** `honest_publish` in the same file (a decided example that publishes a complete, frozen, re-executed record). The negative controls `suppression_breaks`, `modified_evaluator_breaks`, `overwrite_after_check_breaks` show each check is needed.
- **Read depth:** full

### `ControlStack.EvalIntegrity.sc21_undetected_prob`  — `ControlStack/Scenarios/EvalIntegrity.lean:314`
- **Says (plain English):** Fix N reported values and their N true values. Call a result "corrupted" if reported and true values differ; suppose exactly k are corrupted. If the re-execution sample is a uniformly random subset of size B of the N results (every size-B subset equally likely), and re-execution flags any sampled corrupted result, then the fraction of samples that flag nothing is exactly C(N−k,B) divided by C(N,B).
- **Under these hypotheses:** The number of corrupted results is exactly k. "Undetected" is defined in the model as: the sample is disjoint from the corrupted set (so perfect, deterministic detection of any sampled corrupted result is built into the definition). The corrupted set is fixed before the sample is drawn (non-adaptive). World assumptions: the sample is hidden from the agent until after publication; re-execution is deterministic with zero false negatives.
- **Does NOT say:** (a) That the escape probability is small: it is an exact value, which is large when B is small relative to N or k is small (N=100, B=10, k=5 gives about 0.584; k=1 gives 0.9). (b) Anything about an agent that chooses what to corrupt after seeing information about the sample, or adaptively (see `sc21_adaptive*`). (c) Anything about imperfect detection when sampled.
- **Kind:** general theorem (exact counting identity, reusing the `AuditBudget` counting lemma). Note the scenario text says "escapes with probability above" the quantity; this theorem is an equality, so the stated bound is attained, not merely upper.
- **Non-vacuity:** Instantiated numerically for N=100, B=10, k=5 in `sc21_example` (same file), but still under the hypothesis that the corrupted set has size 5. NOT SHOWN as a concrete Lean (reported, true) pair with that property.
- **Read depth:** full

### `ControlStack.EvalIntegrity.sc21_undetected_le_pow`  — `ControlStack/Scenarios/EvalIntegrity.lean:318`
- **Says (plain English):** Under the same setup as `sc21_undetected_prob`, with N positive and B at most N, the probability that a uniformly random hidden size-B sample misses all k corrupted results is at most ((N−B)/N) raised to the power k. In words: drawing the sample without replacement is no worse for the defender than checking each corrupted result independently with probability B/N.
- **Under these hypotheses:** N > 0; B ≤ N; exactly k corrupted results (k ≤ N follows from this). Same world assumptions as above (hidden sample, deterministic perfect re-execution).
- **Does NOT say:** That the bound is small (it is about 0.59 for N=100, B=10, k=5); that the corrupted set may be chosen with knowledge of the sample; anything about imperfect recall.
- **Kind:** general theorem (an inequality between the exact binomial ratio and a power).
- **Non-vacuity:** Same as `sc21_undetected_prob`; numeric instance `sc21_example` (≤ 0.59049) still carries the hypothesis on the corrupted-set size. NOT SHOWN as a concrete pair.
- **Read depth:** full

### `ControlStack.EvalIntegrity.observable_sample_nogo`  — `ControlStack/Scenarios/EvalIntegrity.lean:330`
- **Says (plain English):** Take any fixed re-execution sample S of size B among N results. If k is at most N−B, there is a set A of exactly k results, all outside S, such that the "survival" of A against the single known schedule S is exactly 1. In words: if the agent knows the sample in advance, it can corrupt k unsampled results and is never detected.
- **Under these hypotheses:** S has exactly B elements; k ≤ N − B. The "schedule family" is the single known sample S, i.e. it models an adversary that has observed the sample.
- **Does NOT say:** Anything about how an agent would learn the sample; anything about a partially leaked sample; and nothing about a hidden sample. It is a counting fact that the complement of S is large enough.
- **Kind:** negative control (shows that if the sample is observable, the sampling bound fails completely); the proof is a simple cardinality argument, close to trivial.
- **Non-vacuity:** The hypotheses are satisfiable whenever k ≤ N−B; `AuditBudget.budget_example_observable` gives N=100, B=10, k=5. The conclusion is an existence statement, so no further witness is needed.
- **Read depth:** full

### `ControlStack.EvalIntegrityAdaptive.sc21_adaptive`  — `ControlStack/Scenarios/EvalIntegrityAdaptive.lean:47`
- **Says (plain English):** Tasks are processed in a fixed order as N rounds. In each round the agent decides (possibly at random, and possibly depending on all its own earlier decisions and on the "caught" flags of earlier rounds) whether to corrupt that task's result. A catch flag is raised exactly when the agent corrupts a task that lies in the hidden random re-execution sample S (S uniform over all size-B subsets). The statement: for every such adaptive decision rule, the probability (averaged over the random S) that the agent corrupts at least k tasks and none of the corrupted ones is in S is at most C(N−k,B)/C(N,B). That is the same number as the non-adaptive case, so adaptivity gains nothing.
- **Under these hypotheses:** B ≤ N. The decision rule σ is any function from the visible history (the agent's own earlier corruption bits and the catch flags) to a probability distribution over {corrupt, not corrupt}. Success of the agent is defined as: at least k corruptions and no corrupted round in S. World assumptions, not provable: the real agent learns nothing about S except through catch flags (no timing, side-channel or other leak); detection is deterministic whenever a corrupted task is sampled; tasks are processed in a fixed order the agent cannot change.
- **Does NOT say:** (a) That a real agent sees this much or this little: it is a model of the interface (rounds, bits, flags). (b) Anything when the sample leaks (`leaked_sample_survives` shows survival 1 then). (c) That the bound is small: it is the same number as in the non-adaptive case (about 0.584 for N=100, B=10, k=5). (d) Anything about imperfect detection (see `sc21_adaptive_recall`).
- **Kind:** general theorem (an instance of the F6 hidden-schedule audit theorem `Leakage.audit_adaptive_hidden`).
- **Non-vacuity:** `sc21_adaptive_example` instantiates N=100, B=10, k=5 for an arbitrary decision rule σ, though no concrete σ is exhibited in this file. The kernel `hiddenK σ` is concrete, and σ = any distribution-valued function (e.g. constant) satisfies the hypothesis.
- **Read depth:** full

### `ControlStack.EvalIntegrityAdaptive.sc21_adaptive_content`  — `ControlStack/Scenarios/EvalIntegrityAdaptive.lean:55`
- **Says (plain English):** The same bound as `sc21_adaptive` for a richer model in which each round also has an arbitrary hidden component (task content, monitor flags, extra checks, even checks that depend on the sample S) and an arbitrary joint law with the visible output. The only restriction on the agent is that, for every sample S in the allowed family, every history and each corruption choice a, the probability that the agent makes choice a (summed over all hidden parts and all catch flags) is at most σ(visible history)(a) for some decision rule σ that does not see S. Then the probability, averaged over a uniformly random S, of the event "at least k corruptions, none in S, and no catch flag ever raised by any source" is at most C(N−k,B)/C(N,B).
- **Under these hypotheses:** B ≤ N; the round kernel K is non-negative and sums to at most 1 on each history for every size-B S; the agent's corruption choice has marginal probability bounded above by a rule σ of the visible history only (this is the "no leak about S" assumption, expressed as a hypothesis); σ is a distribution at every history. Success of the agent is defined as having no corrupted round in S and no catch flag at all, so detection of a sampled corrupted task and the effect of the extra checks are built into the definition of the event, not derived. World assumptions: the agent's behaviour really is a function of the visible history only (sample hidden, no side channel); extra checks only add catches.
- **Does NOT say:** That any particular extra check exists or is effective (extra checks can only lower the success probability, never raise it, in this statement); that task content cannot reveal S (the hypothesis on the marginal says it does not, but nothing proves that in a real system).
- **Kind:** general theorem (instance of `ReservedAudit.reserved_adaptive`). Largely a generalisation of the previous theorem; the substantive content is that hidden state does not help the agent provided the leak hypothesis holds.
- **Non-vacuity:** A concrete kernel satisfying all premises is `ReservedAudit.reservedK` (see `reserved_policy_bound` in `ControlStack/Families/F6/ReservedAudit.lean`), for any σ and any flag law; I read that theorem's statement but not the definition of `reservedK` in full. No instance is given in `EvalIntegrityAdaptive.lean` itself.
- **Read depth:** full

### `ControlStack.EvalIntegrityAdaptive.sc21_adaptive_recall`  — `ControlStack/Scenarios/EvalIntegrityAdaptive.lean:68`
- **Says (plain English):** Same setup as `sc21_adaptive_content`, but re-execution may miss: whenever a round is in the sample and the agent corrupted it, the probability of no catch in that round is at most (1−r), where r is the per-history recall (r between 0 and 1). Then the probability, averaged over the hidden uniform sample, that the agent corrupts at least k results and is never caught (by anything) is at most `hypMiss N B k r`, which is the hypergeometric sum: over j from 0 to min(k,B) of C(k,j)·C(N−k,B−j)/C(N,B) times (1−r)^j. That is the exact escape probability of a fixed k-set against a random sample with recall r.
- **Under these hypotheses:** B ≤ N; 0 ≤ r ≤ 1; the same kernel conditions as `sc21_adaptive_content`; an additional per-history condition `hrec` that bounds the joint probability of "agent makes choice a and no catch flag this round" by σ(visible history)(a) times (1−r) when the round is in S and a means corrupting, else times 1. World assumptions: the recall lower bound r holds on every history (re-execution of a corrupted sampled task is detected with probability at least r, with detection events handled history by history), the sample is hidden, no leak about S beyond catch flags.
- **Does NOT say:** That r is any particular value (r is a parameter); that detection events are independent across tasks beyond what `hrec` says; that undetected corruption would be actually harmless or that the number is small (with r = 1/2 and N=100, B=10, k=5 the bound in `ReservedRecall.recall_example` is about 0.79).
- **Kind:** general theorem (instance of `ReservedRecall.adaptive_recall_bound`).
- **Non-vacuity:** `ReservedRecall.recall_instance_bound` in `ControlStack/Families/F6/ReservedRecall.lean` shows the concrete detection-coin kernel `recallK` satisfies all premises; its numeric instance is `recall_example`. Not in this file.
- **Read depth:** full

## SC-22 — Agent misreports interpretability or research findings

**Harm:** k misreported findings escape a hidden independent-replication sample of size B with probability above C(N−k,B)/C(N,B).

**What the Lean claims, taken together, and what they leave to assumptions.** SC-22 reuses the SC-21 sampling arithmetic unchanged: the finding is "misreported" if the reported number differs from the truth number, and replication of a hidden uniform sample of B of N findings catches every sampled misreport. The theorem gives the exact probability that all k misreports avoid the sample, and a separate theorem shows the bound collapses if the sample is observable. Left to assumptions: the replication sample is hidden until after reporting, replication perfectly detects a misreport when sampled (perfect recall; imperfect recall is a different file), and, entirely outside Lean, that a numerically reproducible finding is correctly interpreted. The Lean number is an escape probability (large for small B), not a claim that misreports are detected.

### `ControlStack.EvalIntegrity.sc22_unreplicated_misreport`  — `ControlStack/Scenarios/EvalIntegrity.lean:337`
- **Says (plain English):** Fix N reported findings (as numbers) and N true values. Suppose exactly k reported values differ from their true values. If the replication sample is a uniformly random hidden subset of B of the N findings, and replication flags any sampled finding whose reported value differs from the truth, the probability that nothing is flagged is exactly C(N−k,B)/C(N,B).
- **Under these hypotheses:** Exactly k misreported findings; the misreported set is fixed before the sample is drawn; detection when sampled is perfect and deterministic (built into the definition of "undetected" as "sample disjoint from the misreported set"). It is literally the same statement as `sc21_undetected_prob`, proved by invoking it. World assumptions: the sample is hidden until after reporting; replication detects a misreport whenever it is sampled.
- **Does NOT say:** That a reproduced number is correctly interpreted (the docstring states that replication checks numerical reproducibility under the frozen pipeline, not interpretation); that the probability is small; anything about adaptive misreporters or imperfect replication. The word "findings" is only a relabelling of "results": the statement is about numbers, not scientific claims.
- **Kind:** definitional/trivial (a renaming of `sc21_undetected_prob`; the proof is one application of it). The underlying counting identity is nontrivial but standard.
- **Non-vacuity:** NOT SHOWN as a concrete pair (reported, true) with the k-misreport property; see `sc21_example` for the numeric N=100, B=10, k=5 instance (same hypothesis).
- **Read depth:** full

### `ControlStack.EvalIntegrity.observable_sample_nogo`  — `ControlStack/Scenarios/EvalIntegrity.lean:330`
- **Says (plain English):** If the replication sample S (size B among N findings) is known to the agent in advance and k ≤ N−B, there exist k findings outside S that the agent can misreport and the survival probability against the known schedule is exactly 1.
- **Under these hypotheses:** S has B elements; k ≤ N−B. The schedule family is the single fixed set S. For SC-22 it is the statement that, if the replication sample is not hidden, the misreport bound gives no protection.
- **Does NOT say:** How the agent would learn S, or anything about a hidden sample.
- **Kind:** negative control (shows the sample_hidden assumption is load-bearing); the proof is a cardinality argument.
- **Non-vacuity:** Satisfiable whenever k ≤ N−B; numeric instance in `AuditBudget.budget_example_observable` (N=100, B=10, k=5).
- **Read depth:** full

## SC-23 — Prompt-injected document/tool result causes an unauthorized tool action

**Harm:** A sensitive action whose authorization-relevant arguments derive (through label-propagating steps) from tool results executes without a fresh user confirmation of exactly its tool and values.

**What the Lean claims, taken together, and what they leave to assumptions.** There are three model generations. In the first (`SC23Injection`), values carry a label and a ghost provenance bit; a sensitive action on a tainted-labelled value runs only with a matching one-use user confirmation. The "untrusted" status is whatever the model's derivation rule says, and that model lets a derivation with no sources produce an untainted value of arbitrary content, so laundering is excluded by a premise (provenance_truthful). In the second and third (`SC23Isolation`, `SC23IsolationV2`) laundering is excluded structurally: the planner's state contains only user-typed values or opaque handles to quarantined tool results, and a noninterference theorem shows changing tool-result content cannot change planner state; sensitive actions with a handle argument need a user confirmation of exactly the resolved values. Authentication of confirmations (and, in V2, of user input and halt) is added by wrapping each operation with its true issuer, so a forged claim is a no-op. What is left: credential separation (the issuer reported by the platform is the true issuer), the planner really runs only on its own state (no side channel from quarantined processing), the confirmation UI shows exact values, and non-sensitive tools and the wisdom of confirmations are out of scope. The isolated models do not track one-use of confirmations (the first model does).

### `ControlStack.SC23.sc23_safe`  — `ControlStack/Scenarios/SC23Injection.lean:300`
- **Says (plain English):** After any sequence of operations from the empty state (user inputs, tool results, derivations with arbitrary content from arbitrary stored values, confirmations by any caller number, sensitive or non-sensitive actions with any arguments), every executed action whose tool is on the sensitive list and whose arguments truly depend on a tool result (the ghost provenance bit is true) has a recorded user confirmation with the same tool and exactly the same argument values, made by a caller on the user list. Also, no confirmation is used by more than one executed action.
- **Under these hypotheses:** All checks on ("full"): a derived value is labelled tainted iff some source is; an action on a sensitive tool with any tainted-labelled argument needs a confirmation whose tool matches, whose values equal the resolved argument values exactly, and whose nonce has not been used; only callers in the user list may confirm. In this model "provenance" is not independent ground truth: the ghost bit is computed by the same operation rules (tool results are provenance-true, user inputs false, derived = any source true). World assumptions: that the only way untrusted content enters the system is through the model's tool-result operation, and that a derivation never takes untrusted content as input except through its listed sources (provenance_truthful); that confirmations are issued only by real users (credential separation) and the confirmation UI shows exact values.
- **Does NOT say:** (a) That laundering is impossible in practice. In this model a derivation with an empty source list yields an untainted value of arbitrary content, so a planner that copies injected text into such a derivation bypasses the check; the header excludes this by premise. (b) That a user's confirmation is wise, or that untainted values are correct. (c) Anything about non-sensitive tools. (d) That the user-input operation is by a real user: in this model it carries no caller at all.
- **Kind:** general theorem (inductive invariant over all traces, with label = provenance as the key invariant).
- **Non-vacuity:** `honest_untainted` and `honest_confirmed` (decided examples in the same file) show an untainted sensitive action and a confirmed tainted one both run. Necessity witnesses `summarizer_drops_taint`, `no_taint_check_breaks`, `paraphrase_confirmation_breaks`, `confirmation_reuse_breaks` show each check matters.
- **Read depth:** full

### `ControlStack.SC23.halt_freezes`  — `ControlStack/Scenarios/SC23Injection.lean:315`
- **Says (plain English):** If the model's state is already marked halted, then running any further list of operations leaves the state exactly unchanged: no new values, confirmations, or executed actions appear.
- **Under these hypotheses:** The halted flag is true in the starting state, under the full checks (the halt check is on). The flag is set only by a halt operation whose caller number is in the admin list.
- **Does NOT say:** That a halt ever happens, that it happens in time, or that the halt caller is a real administrator (credential separation is a premise); that actions already executed before the halt are undone.
- **Kind:** general theorem (the sticky halt bit makes every operation the identity; close to definitional by construction).
- **Non-vacuity:** Not exhibited as an example in the file; the hypothesis is satisfiable (a state reached by a halt operation by an admin, e.g. `halt 9` in policy `P0`), but NOT SHOWN as a Lean example.
- **Read depth:** full

### `ControlStack.SC23Isolation.noninterference`  — `ControlStack/Scenarios/SC23Isolation.lean:235`
- **Says (plain English):** Take two lists of operations that are identical except that some tool-result operations carry different content values (position by position, the lists have the same length and the same operations; only the contents of tool results differ). Run both from the empty state under the full checks. Then the two final states agree on: the list of user inputs, the planner's list of values (trusted values and handle indices), the number of quarantined values, and the halted flag. So injected content cannot change anything the planner holds.
- **Under these hypotheses:** The environment (users, admins, sensitive tools, the planner program `plan`, the quarantined transformer `qf`) is arbitrary but identical for both runs. The planner's derivation is a function of the trusted user inputs and a step counter only (it cannot inspect handles or content), tool results enter a separate quarantine and the planner receives only an index, and the operation that would let the planner read quarantine content is a no-op in the full configuration. World assumptions: the real planner really is restricted to its own state (no side channel from quarantined processing into the planner, e.g. shared context, logs or error messages); user input is authentic (in this version `userInput` has no caller).
- **Does NOT say:** That the executed action list is the same across the two runs: resolved argument values of quarantined handles do differ, and the theorem does not compare them; that the planner's own program is good; anything about the confirmation channel.
- **Kind:** general theorem (a relational invariant over pairs of traces; structural isolation is a property of the model's types).
- **Non-vacuity:** `derive_ignores_tool_content` (a short computation) and `w1_impossible` (below) show the isolated planner still derives non-trivial values and acts; `no_isolation_launders` shows that dropping the isolation check breaks the property.
- **Read depth:** full

### `ControlStack.SC23Isolation.w1_impossible`  — `ControlStack/Scenarios/SC23Isolation.lean:376`

So the review's laundering trace (injected 66 reaching the sensitive tool as trusted) does not occur.
- **Under these hypotheses:** The fixed example environment `E0`, full checks, one specific trace. Nothing is quantified over environments or traces.
- **Does NOT say:** That laundering is impossible in general (that is `noninterference`); that this specific planner is sensible. It is a decided finite computation.
- **Kind:** finite computation (decide/native), a concrete instance of the general noninterference theorem.
- **Non-vacuity:** The example runs and executes an action; it is the witness itself.
- **Read depth:** full

### `ControlStack.SC23Isolation.sc23_isolated_safe`  — `ControlStack/Scenarios/SC23Isolation.lean:314`
- **Says (plain English):** After any list of operations from the empty state, every executed action on a sensitive tool whose arguments include at least one quarantined handle (flagged "tainted" in the log) has a recorded user confirmation with the same tool, the same nonce as the one used, exactly the resolved argument values, and made by a caller on the user list.

## SC-24 — Untrusted monitor colludes with generator or learns honeypot phase

**Harm:** A colluding monitor passes real attacks while flagging honeypots, or honeypot-measured recall misstates real recall. The claimed bounds: success at telling real attacks from honeypots is at most (1+TV)/2, and the gap between real and honeypot pass rate is at most TV, where TV is the total variation distance between the view distributions.

**What the Lean claims, taken together, and what they leave to assumptions.** The four theorems are classical bounds on a monitor whose decision depends only on a stated view of each item: the gap between its pass rates on honeypots and on real attacks is at most TV (`pass_transfer`); its one-shot success at "pass real, flag honeypot" under a 50/50 prior is at most (1+TV)/2 (`collusion_uniform`); a shared-codebook covert message through a canonicalised view of K classes is decoded with probability at most K/|messages| (`canon_channel`); and a monitor learning a hidden phase over m items from bounded per-item leakage guesses correctly with probability at most L^m/2 (`phase_learning`). Everything is conditional on parameters the theorems do not control: TV (which a colluding generator is trying to enlarge, e.g. with a steganographic flag, where TV=1 and the bound is vacuous), the canonicalisation size K, and the per-item leakage; and on the premise that the monitor's decision really depends only on the stated view. These bounds are not a detection guarantee: they say the honeypot measurement transfers up to TV, which is useful only if TV is shown to be small.

### `ControlStack.MonitorCollusion.pass_transfer`  — `ControlStack/Families/F6/MonitorCollusion.lean:65`
- **Says (plain English):** Let the honeypot views and the real-attack views each follow a probability distribution over a finite set of possible views. Let the monitor, on seeing a view v, pass it with probability β(v) between 0 and 1 (any randomised rule that depends only on the view). Then the monitor's pass rate on real attacks and its pass rate on honeypots differ by at most the total variation distance (half the sum of absolute differences of the two distributions).
- **Under these hypotheses:** Both view laws are genuine probability distributions (non-negative, sum 1); the decision rule depends on the view only (no other input such as timing, ordering or memory of other items), with pass probability in [0,1]; the view set is finite. A false-negative rate is the pass rate on attacks, so this is the bound on the difference of the real and honeypot false-negative rates. World assumptions: the monitor's decision really depends only on the stated (canonicalised) view; TV between the real distribution of views and the honeypot distribution is small (it must be estimated or enforced; nothing here bounds it).
- **Does NOT say:** That honeypot measurements are valid: if a colluding generator makes real attacks distinguishable from honeypots then TV is large and the bound is vacuous (`stego_fools_honeypots` has TV = 1). That honeypot-measured recall is within TV for a monitor that sees side information not in the view. That the bound holds across a stream of dependent items; it is one decision, per item, with the view laws fixed.
- **Kind:** general theorem (a standard inequality: expectation of a [0,1]-valued function under two distributions differs by at most TV).
- **Non-vacuity:** `stego_fools_honeypots` and `canon_restores` (same file) instantiate it for specific view laws (TV = 1 and equal laws respectively). No example in which TV is small and the monitor is non-trivial is given.
- **Read depth:** full

### `ControlStack.MonitorCollusion.collusion_uniform`  — `ControlStack/Families/F6/MonitorCollusion.lean:118`
- **Says (plain English):** Pick a phase uniformly at random: with probability 1/2 the item is a real attack, with probability 1/2 it is a honeypot. A view is drawn from the real-attack distribution or the honeypot distribution accordingly; the monitor (a randomised rule depending only on the view) outputs pass or flag. The colluder succeeds on this item if it passes a real attack or flags a honeypot. Then its success probability is at most (1 plus TV between the two view distributions) divided by 2; equivalently its advantage over a coin flip is at most TV/2.
- **Under these hypotheses:** Both view laws are distributions; the monitor's output on a view v is a distribution over pass/flag; the prior on phase is exactly uniform; a single item (one-shot); the decision depends only on the view v. World assumptions: complete mediated view (no side input to the monitor); TV is bounded or estimated; fresh phase per item.
- **Does NOT say:** (a) That the colluder cannot pass every real attack in a long stream and flag every honeypot: the bound is for one item with a 50/50 prior (the general-prior form `collusion_ml` is a separate theorem), not a bound on a joint event over many items. (b) That TV is small: the colluding generator chooses the real-attack view law, so TV is the quantity the adversary tries to maximise; at TV = 1 the bound is 1. (c) Anything about shared secrets or adaptivity across items (see `phase_learning` for streams).
- **Kind:** general theorem (an instance of the one-shot maximal-leakage transfer `collusion_ml`, with sum of pointwise maxima equal to 1 + TV).
- **Non-vacuity:** No example with a specific monitor and numbers; the hypotheses are satisfiable by any two distributions and any monitor kernel, e.g. the `stego*` laws in the same file satisfy the distribution hypotheses (bound = 1 there). NOT SHOWN as an explicit instance with a small TV.
- **Read depth:** full

### `ControlStack.MonitorCollusion.canon_channel`  — `ControlStack/Families/F6/MonitorCollusion.lean:140`
- **Says (plain English):** A generator and a monitor share a codebook (an encoder and decoder fixed in advance, possibly randomised). The generator embeds a message drawn uniformly from a finite set M into the view. A trusted canonicalisation maps each view to one of K classes, and the monitor decodes from the class only. Then the probability that the decoded message is correct is at most K divided by the number of messages, i.e. at most log base 2 of K bits of covert information per item get through.
- **Under these hypotheses:** M finite and nonempty; the encoder gives a distribution over views for each message; the decoder gives a distribution over messages for each class; the canonicalisation is a fixed function into K classes; the message is uniform. World assumptions: the canonicalisation is trusted and actually erases everything else (the monitor sees the canonical class only, complete mediation), and the generator and monitor have no other channel (e.g. timing, ordering, metadata).
- **Does NOT say:** That K is small (it only bounds signalling by log K bits; the semantic content of an attack may itself need many bits); that canonicalisation keeps the attack detectable; that the shared codebook is the only form of collusion; anything about the monitor's detection quality. The bound is vacuous when K is at least the number of messages.
- **Kind:** general theorem (counting bound for a covert channel pushed through the K-class map; reduces to the unmapped covert bound).
- **Non-vacuity:** `canon_restores` (same file) uses the K = 1 canonicalisation on the stego example, but only shows pass rates coincide when the monitor sees nothing. No example of this bound with non-trivial K and M is given, so NOT SHOWN.
- **Read depth:** full

### `ControlStack.MonitorCollusion.phase_learning`  — `ControlStack/Families/F6/MonitorCollusion.lean:203`
- **Says (plain English):** A hidden phase, test or deployment, is chosen uniformly and then fixed for a stream of m items. In each round the model produces a visible output (views, the monitor's actions, feedback) and possibly hidden state, with arbitrary dependence on the whole history so far (hidden and visible). Suppose that in every round, whatever the phase and the history, the probability of each visible output (summed over hidden state) is at most the value of a phase-independent certificate, and the certificate's total mass over outputs is at most L. Then any final guess of the phase, which may be randomised and depend on the visible transcript, is correct with probability at most L to the power m, divided by 2.
- **Under these hypotheses:** Kernel entries non-negative; a certificate c that dominates every phase's round law at every history; L at least 0 and an upper bound on the total mass of the certificate at every visible history; the guess is a distribution over phases for each visible transcript; uniform prior; the phase is constant across the stream. World assumption: the per-item leakage bound L is valid for every history (worst case over history) and phases are re-randomised before L^m reaches 1 (about 1/λ items for L = 2^λ). L itself must be estimated or enforced; this theorem does not bound it.
- **Does NOT say:** That the phase cannot be learned: L^m grows exponentially and the bound is at least 1 (vacuous) once L^m ≥ 2; nothing about a phase kept fixed for a long deployment; nothing about adaptive signal search by a colluding generator beyond what L captures (the scenario notes this is untested at runtime). The Lean statement does not require the kernel sum to be at most 1.
- **Kind:** general theorem (an instance of the sequential maximal-leakage transfer `Leakage.seq_transfer_const` plus a bound on the certificate's mass).
- **Non-vacuity:** `phase_example` (same file; but not in this list): a binary-symmetric leak with crossover 99/200 per item, m = 10, gives guess probability < 0.553 for every adaptive guesser. The premises are checked there (`bscK_dist`).
- **Read depth:** full
