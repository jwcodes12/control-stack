# Held-out monitor-score data search (2026-10-07)

Method: web search + page fetches only (summaries from a fetch tool; NOT downloaded or inspected). Everything below is "as reported by the landing page" unless noted. UNVERIFIED = not confirmed.

## Ranked candidates

### 1. Redwood Control Leaderboard datasets (BashArena / bashbench2_v1, LinuxArena 217, LaStraj 2.0, PostTrainBench) -- BEST
- URL: https://control-leaderboard.redwoodresearch.org/data (public runs, no auth reported)
- Format: Inspect .eval logs; per-sample monitor scores under `scores.monitor_<monitor>@<trusted model>`.
- BashArena (bashbench2_v1, with UK AISI): 600 honest / 600 attack, MIT, monitor scores YES. Task definitions: HF Eccentricity/bashbench2 (637 tasks, CC-BY-SA-4.0, no trajectories).
- LinuxArena 217: 250 honest / 150 attack, monitor scores YES, license not shown. LaStraj 2.0: 30 honest / 17 attack (human-crafted attacks), CC BY 4.0, scores YES. PostTrainBench: 48/72, scores YES, license not shown.
- Splits: only honest/attack labels; no predeclared train/test split found. But task IDs exist, so WE could freeze a split (e.g. by task id) before touching scores -- a self-imposed predeclaration, not a published one.
- Fit as deployment-matched held-out: moderate-good. Single fixed monitor+task distribution, n=600/600 gives usable bands at coarse FPR (~1% FPR needs >=~300 honest for non-trivial bands). Caveat: attack trajectories are model-generated by a specific attack policy; "attack" success filtering (LinuxArena paper compares honest vs SUCCESSFUL attacks) must be matched to the certifier's attack-label definition. Multi-step trajectories: need a per-trajectory (max-over-steps) score definition; check which score field is used.
- LinuxArena paper: https://arxiv.org/abs/2604.15384 (20 envs, 1,671 main tasks, 184 side tasks). Not verified whether the leaderboard samples are drawn iid from a deployment distribution.

### 2. Async Control (UK AISI) -- https://arxiv.org/abs/2512.13526 ; code https://github.com/UKGovernmentBEIS/async-control (MIT)
- 5 SWE environments; ensemble monitor reports "6% FNR at 1% FPR on a held out test environment" -- a genuine held-out-environment protocol. Repo has scripts to GENERATE honest/attack trajectories (generate_trajectories.py, analyse_trajectories.py); UNVERIFIED whether pre-generated logs/scores are released (none seen). Needs API spend to regenerate. Best published held-out design, weakest data availability.

### 3. HF jprivera44/exp2_transcript_monitor_results (APPS backdoor, collusion)
- https://huggingface.co/datasets/jprivera44/exp2_transcript_monitor_results ; license not shown.
- 8,768 rows; train 7,570 / test 1,200; label 0 clean / 1 backdoor; code + problem text. No stored monitor scores (it is a fine-tuning-of-detector dataset) -- we would have to score it with a fixed monitor. Real published train/test split, APPS single-action setting (matches Greenblatt). Fixed-monitor scoring of the 1,200 test rows is cheap. Backdoors here include collusion-signal buckets; use only clean vs backdoor_only for an honest/attack ROC. Fit: good for a cheap, exactly-predeclarable test. Caveat: provenance/quality of third-party dataset UNVERIFIED.

### 4. HF RoganInglis/apps-backdoors (ControlArena APPS) -- https://huggingface.co/datasets/RoganInglis/apps-backdoors
- MIT. 5,000 APPS problems, 4,180 verified backdoor solutions (is_backdoor_sample flag, exploit inputs, validity flags). NO monitor scores, single train split. Honest solutions are in the data (multiple solution variants); we would score with our own monitor and could define the held-out split by problem id up front. This is the closest public analogue of the Greenblatt setting. Redwood's original 2023 released data: I could not find a public monitor-score release (UNVERIFIED/not found).

### 5. Scale AI MRT (Monitor Red Teaming) -- https://huggingface.co/datasets/ScaleAI/mrt
- CC BY-NC 4.0; 11.5 GB; SHADE-Arena (17) + CUA-SHADE-Arena (15) tasks; transcripts, monitor verdicts, adversarial evasion strategies; one "validation" split (viewer broken). Exact honest/attack counts UNVERIFIED. Related: leaderboard lists SHADE-Arena as 374 honest / 308 attack, CC BY-NC, no monitor scores. Non-commercial license; tasks are few so samples per task are clustered (non-iid) -- weaker fit.

### 6. MonitoringBench (BashArena) -- https://arxiv.org/abs/2605.09684
- 2,644 attack trajectories, CC BY 4.0, attack-only, no monitor scores (leaderboard). Pipeline optimised on 3 dev monitors, tested on 10 held-out monitors -- held-out over MONITORS, not samples. Needs honest pairing from BashArena. Adversarially optimised attacks: not deployment-matched.

### 7. LASR repo itself -- https://github.com/NelsonG-C/lasr-labs-2025-control-project
- 491 commits; src/, tests/, docs/; APPS and BigCodeBench; several collusion strategies (passive self-recognition, causal, acausal, combined) and finetuning/prompt-optimisation side experiments. I did not inspect directory contents, so whether other conditions/seeds or a held-out split exist is UNVERIFIED -- worth a direct `git clone` look (BigCodeBench runs are a natural second sample; same protocol, different task distribution).

### Not found / not verified
- Ctrl-Z (2504.10374): BashBench task data exists (257 tasks); I found no public release of per-sample monitor scores. UNVERIFIED.
- ControlArena (https://github.com/UKGovernmentBEIS/control-arena, MIT): library only; no released trajectory logs found beyond the datasets above.
- METR monitorability, Apollo: no per-sample monitor score datasets found (not searched deeply).
- Basic Legibility Protocols (2602.10153), Decorrelation/Skill monitor ensembles (2608.16190, 24 open monitors, pAUC): APPS-based, data/code release UNVERIFIED -- possible per-sample scores for many monitors; check PDFs.

## Prior art on statistical certification (thin)
- Searches found NO paper on rigorous (simultaneous/Clopper-Pearson) ROC certification of AI-control monitors. Closest: "Sound Probabilistic Safety Bounds for LLMs" (arXiv 2607.20286), "Estimating Uncertainty in Classifier Performance ... LLMs and Nested Data" (2606.26422), "From Probe Scores to Alarm Policies" (2610.04575; bootstrap CIs on FPR/TPR for activation monitors), Games for AI Control (2409.07985, no CIs on ROC), LinuxArena/Async Control (bootstrap-style reporting, not verified). Not read in detail. Reasonable novelty claim, but check these before asserting it.

## Recommendation (single best next step)
Use BashArena bashbench2_v1 (600 honest / 600 attack, MIT, per-sample monitor scores, Inspect .eval) from the Control Leaderboard: download, pick ONE monitor field and ONE per-trajectory score definition, commit (hash) a split by task id and the threshold grid BEFORE reading scores (e.g. calibrate band design on half, certify on the other half), then run the checker. In parallel, as a cheap APPS-faithful second test, score the 1,200-row test split of jprivera44/exp2_transcript_monitor_results (clean vs backdoor_only) with one fixed monitor.

## Orchestrator verification (2026-10-07, direct fetches)
- `https://control-leaderboard.redwoodresearch.org/monitors.json` (public, generated 2026-09-24) carries PER-SAMPLE,
  per-action monitor scores (`score_samples`, with trajectory ids and side-task success) for the default dataset only:
  LaStraj 2.0 (30 honest / 17 attack, CC BY 4.0), 19 monitor configurations. Saved with SHA256 in
  `data/redwood-leaderboard/`. Other datasets are not served by any public JSON (site JS fetches only this file).
- BashArena 600/600: raw honest eval is on the public viewer; the attack eval and all monitored copies are not public
  ("Honest/Attack · monitored" columns empty).
- LinuxArena 217 (Opus 4.8, 250 honest / 150 attack): monitored evals exist (runs 5d1afbf1…, 35f6ec52…) but return
  HTTP 401 (login required until published).
- Data-use condition on the site: evaluation only; do not train on it or send it to services that retain data.
- Conclusion: no public, predeclared, held-out per-sample score set of useful size exists today. Options:
  (a) predeclare and certify on LaStraj now (valid but tiny: bands will be wide);
  (b) request EquiStamp/Redwood access to the LinuxArena 217 monitored runs (250/150), then predeclare a split;
  (c) score a public held-out split ourselves with a fixed trusted monitor (e.g. the 1,200-row APPS test split on HF,
      or BashArena raw honest + a public attack set), which costs API calls.

## Follow-up (John's notes, checked 2026-10-07)
- **LASR "When can we trust untrusted monitoring?" data IS a held-out test split.** The LASR code assigns even record
  indices to `even_test`; all 43,698 sample ids in our local archive are even. Used in `PREREG-LASR-TEST.md`.
- **LinuxArena 217 monitored evals:** re-checked at ~22:00 UTC; still HTTP 401 for both runs.
- **Prior art confirmed:** `rocci` (PyPI, https://pypi.org/project/rocci/) gives distribution-free simultaneous ROC
  confidence bands. Gao, "From Probe Scores to Alarm Policies: Operational Validity of Activation Monitors for
  Language-Model Agents", arXiv:2610.04575 (DAI 2026): frozen targets, calibration/test separation, false-alarm budgets,
  abstention when evidence is insufficient. Classical: exact/distribution-free ROC bands (e.g. PubMed 1857255;
  Macskassy & Provost, NYU CeDER-05-12).
- **Novelty statement to use:** not "simultaneous ROC bands" (known). At most: exact finite-sample simultaneous ROC
  bands fed into a machine-checked (Lean, kernel-evaluated) worst-case control-game certificate against adaptive
  red-team policies, evaluated on frozen monitors and held-out trajectories. Not yet checked: whether rocci's bands
  are tighter than our Bonferroni Clopper–Pearson bands (likely; could be swapped in if they output rational endpoints).
- Not yet examined: Scale MRT / SHADE-Arena (CC BY-NC; many monitors per trajectory, so not independent samples) and
  TraceGuard (279/240 BashArena; holdout status unclear) as secondary stress tests.
