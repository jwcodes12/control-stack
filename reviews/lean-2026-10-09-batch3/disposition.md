# Disposition: Gemini 3.1 Pro review of LabStack, SC26Liveness, SC27ExtensionOnly and SC25Refinement

| File | Finding | Disposition |
|---|---|---|
| LabStack | The deputy only issues `execute`, so it cannot pay without an SC-26 approval. | **Intended.** An admissible deputy acts only through the gate's own approval (`Compose.admissible_of_step`). A deputy that could approve on its own is exactly the confused-deputy witness (`deputy_reuse_breaks_sc26`). No change. |
| LabStack | Authenticated provenance is set disjointness. | **Same as batch 2.** The content is in `authRun`: an operation claiming identity x takes effect only if x issued it. Issuer authenticity is the explicit premise. No change. |
| LabStack | ℕ subtraction in the budget check could truncate if SC-26's spend decreased. | **Not reachable.** SC-26's spend never decreases (`SC26Liveness.Mono`/`run_mono`; spend is only incremented), and `global_budget` is proved over all reachable states. The reliance on monotonicity is noted here as fragile; an ℤ-based restatement would remove it. |
| LabStack | `lab_halt_freezes` lets arrivals through. | **The statement says this explicitly:** only messages already in flight may land. This is the same in-flight semantics as `SC26.halt_freezes`. No change. |
| SC26Liveness | A fixed schedule shape (recover … bankProcess) and no halt before recovery. | **This is the fairness premise, stated as such** (cf. `HaltLiveness.DeliveredWithin`). `crashes_forever_no_progress` shows it is necessary. Temporal-logic phrasing is future work. |
| SC26Liveness | The wire is append-only; crashes never lose messages. | **Closed** by `SC26LossyLiveness` (drop, duplicate and reorder: safety unchanged, `lossy_safe`; bounded-loss fairness gives liveness, `lossy_rounds`; an all-drop adversary blocks progress, `drop_all_no_progress`). The original note follows: the model assumes no network loss. Retransmission after a loss is the same `recover` path (it resends unacknowledged intents), but message loss is not modelled. Reliable transport is added as a premise. |
| SC26Liveness | The cap-exhaustion disjunct is trivial. | **Intended.** The theorem characterises exactly when progress can fail. `cap_exhausted_blocks` states the availability cost. No change. |
| SC27ExtensionOnly | After a fork alarm, anchoring stops for good. | **Valid. This is fail-closed by design,** and it has an availability cost. Recovery needs an out-of-band, operator-acknowledged re-anchor, which is not modelled. Documented. |
| SC27ExtensionOnly | `Set.InjOn` is trace-dependent. | **This is the standard trace-level form of collision resistance** (global injectivity is impossible for compressing hashes; see the batch-1 review). No change. |
| SC27ExtensionOnly | `alarm_iff` is definitional. | **Agreed.** It is a sanity lemma, not a result. |
| SC25Refinement | Atomic `fire` maps to `[check, fire]`; `checked` is a ghost. | **Agreed on scope.** The refinement shows that the single-threaded runtime implements the model's safe configuration. It does not analyse a race, because the runtime has none. The time-of-check/time-of-use (TOCTOU) witness (`nonatomic_check_race_breaks`) is about non-atomic designs. Wording kept accordingly. |
| SC25Refinement | Content safety is "just" injectivity. | **Agreed that the core step is injectivity.** The state-machine content is the invariant tying audit rows to journal contents. No change. |
